# 智美医美顾问 v2.0

面向医美机构的 **AI 顾问系统**：C 端顾客咨询项目 / 查门店资质 / 改约，
坐席端接管 AI 答不了、或不该答的问题。

> **设计的出发点不是"让 AI 回答得更多"，而是"让 AI 不回答它不该回答的"。**
> 所有出站内容必须经过硬性规则 + 三份审查面板，拿不到放行凭据就不出站；
> 审查不过就转人工，绝不"装作通过"。

## 系统长什么样

**四栏布局，栏间可拖动调整宽度**（键盘也能调：分隔条可聚焦，带 `role="separator"`）：

```
┌──────────┬──────────────────┬────────────────────┬──────────────────────┐
│ 历史对话  │ 对话              │ 工作流架构          │ 执行轨迹              │
│          │                  │ 本次 27 节点·2 子图 │                      │
│ ＋新对话  │ （逐字呈现的      │ 本次经过：          │ 1 输入标准化    41ms │
│ ·术后不适✕│   已审正文）      │  [✓入口] [✓七路]   │ 2 意图与槽位  1280ms │
│ ·项目咨询✕│                  │  [✓科普] [✓风险]   │   └ 展开看输出       │
│          │ 人工客服处理中…   │  ┌──分层架构图──┐   │ 3 分派          12ms │
│          │ [继续补充情况…]   │  │ 走过的点亮  │   │ …                    │
└──────────┴──────────────────┴────────────────────┴──────────────────────┘
```

- **架构栏**按 `Workflow/langgraph-main.mmd` 分六层绘制，走过的节点依次点亮、连线流动；
  顶部直接回答"这一次经过了哪几层、哪几个子图、各几步"。
- **轨迹栏**按顺序列出真正执行过的节点（含子图内部节点），点任意节点可展开**它写回的状态**。
- 两者**同屏但各自独立成窗**：滚一个不会把另一个滚跑。

## 九个 Agent 与一道必经的风险门

```
用户输入
  → normalize 输入标准化与授权校验
  → emergency_screen 紧急筛查（命中即走固定模板 + P0 工单，措辞不走模型）
  → classify 意图与槽位 → dispatch 分派
  → 七路草稿产出：k_agent 科普 · r_agent 推荐 · c_agent 资质 · b_agent 预约
                  p_agent 术后 · clarify 澄清 · emergency_draft 急诊
  → aggregate 汇聚
  → 【风险审查子图 · 必经】硬性规则 + 医疗/广告/隐私三份面板意见 → 裁决 → 签发放行凭据
  → 五档出口：pass / revise / need_info / block / human
  → send（校验凭据）· human_handoff（建工单）· audit_block
```

其中 **知识科普子图**内部另有完整链路：检索 → 证据筛选 → 草稿/降级/追问 → 逐句核对引用。
子图里的每一次核对失败都会**掉头重写**，而不是"当作通过"。

## 快速开始

```bash
cd Code

# 1) 起依赖（Postgres + Milvus）
docker compose -p zhimei up -d

# 2) 装依赖（推荐 uv）
uv venv && uv pip install -r requirements.txt

# 3) 配置：复制 .env.example 为 .env，填 DEEPSEEK_API_KEY
# 4) 建表 + 灌演示数据（含知识库与演示账号）
psql "<PG_DSN>" -f sql/schema.sql
python scripts/seed_kb.py

# 5) 起服务
python -m app.api --port 8090
#   C 端        http://127.0.0.1:8090/chat
#   坐席工作台   http://127.0.0.1:8090/ops/panel
```

环境体检与自测：

```bash
python scripts/check_env.py        # 逐项检查依赖/端口/表/知识库，并告诉你下一步做什么
python scripts/smoke.py            # 96 项不变量断言（不需要外部依赖）
```

> 想先看效果又不想装 Postgres / Milvus / 模型？用 `--profile fake`：
> 内存存储 + 脚本化假模型，零外部依赖：
> `python -m app.api --profile fake --port 8077`

## 已经做实的几件事

- **强制风险门**：任何出站内容都持有绑定 `content_hash` + `plan_hash` 的放行凭据，
  改一个字节即作废；被阻断的内容不产生任何业务出站。
- **三条预算**：修订 2 次 / 澄清 2 次 / 子图内核对 3 轮 —— 预算耗尽不是一律降级，
  软问题（措辞过头）修一轮就放行，硬问题（无依据）才降级。
- **转人工是一条完整链路**：系统判定转人工、用户主动要求转人工（连续三次门槛 +
  安抚回复）、接管期间顾客仍可发言（AI 不答但记录）、坐席关单后 AI 自动恢复。
- **可解释的执行过程**：节点级执行轨迹（可展开每个节点写回的状态）+
  按设计图绘制的工作流架构，两者同屏、各自独立滚动。
- **隐私最小暴露**：脱敏在服务端出口做；坐席队列只显示发起人名字的第一个字；
  顾客可以**真删除**自己的对话（含另一个 schema 里的图状态），并如实告知哪些审计记录按合规保留。
