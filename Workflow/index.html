NODE CATALOG / OPEN-WEIGHT DEPLOYMENT

每个 Agent 的内部节点与模型职责

模型负责理解、提取和表达；检索模型负责召回资料；规则和业务系统负责真实状态、权限、执行与最终判定。

文本模型 Qwen3 系列视觉模型 Qwen3-VL 系列检索模型 BGE 系列规则 / 工具 不调用大模型
01 / SUPERVISOR

总控调度 Agent

  • 输入标准化与会话关联规则 / 工作流绑定会话、用户、渠道和任务状态。
  • 多意图识别与字段抽取Qwen3-8B高频结构化理解，输出意图、槽位和优先级。
  • 任务规划与结果聚合Qwen3-30B-A3B编排多 Agent 结果，形成待审草稿。
  • 重试、状态与审计规则 / 工作流控制回路，任何最终内容均送风险审查。
02 / INTAKE

意图识别与分流 Agent

  • 紧急信号预筛规则引擎命中经审核的紧急词和高风险事件即优先升级。
  • 意图分类与槽位提取Qwen3-8B识别科普、预约、术后等意图及项目、时间、症状字段。
  • 路由映射规则配置按意图和风险标签分发至专业 Agent。
03 / KNOWLEDGE

知识科普 Agent

  • 边界判断与检索问题改写Qwen3-8B把自然问题拆成项目、流程、恢复期等检索子任务。
  • 混合检索与资料排序BGE-M3 + Reranker从审核知识库召回并排序相关证据。
  • 证据充分性与冲突检查Qwen3-32B → R1Qwen 先核对；高影响或冲突时由 DeepSeek-R1 独立复核。
  • 科普草稿生成Qwen3-30B-A3B用通俗语言说明，保留限制条件和面诊提示。
04 / RECOMMENDATION

项目推荐 Agent

  • 画像授权与候选过滤权限 / 数据库只读经授权信息，过滤下架、预算或门店不符项目。
  • 需求与预算提取Qwen3-8B提取明确需求、预算、恢复期和时间偏好。
  • 推荐组合与理由Qwen3-30B-A3B输出可优先了解的方向和仍需确认事项。
  • 价格与活动校验业务系统价格仅取正式业务记录，模型不得估价。
05 / CLINIC INFO

资质与门店查询 Agent

  • 门店、医生、项目识别Qwen3-8B将用户口语映射为可查询实体。
  • 资质、设备与排班查询机构数据库以正式数据源为唯一事实依据。
  • 查询结果说明Qwen3-30B-A3B把已验证数据转换成易读回复。
06 / BOOKING

预约管理 Agent

  • 预约请求解析Qwen3-8B提取预约、改约或取消所需参数。
  • 身份、归属和档期校验预约系统校验权限、真实号源、费用规则与操作条件。
  • 确认与结果文案Qwen3-30B-A3B基于真实结果生成待审确认内容。
  • 幂等执行业务系统仅在用户确认与风险放行后执行。
07 / PROFILE & MEMORY

客户画像与记忆 Agent

  • 授权、脱敏与保留期限隐私服务决定信息能否写入、何时归档或删除。
  • 偏好与事实抽取Qwen3-8B从对话中提取明确表达，并保留来源证据。
  • 长期摘要与冲突标注Qwen3-8B压缩长对话，标记前后不一致但不替用户裁决。
08 / POST-CARE

术后护理与随访 Agent

  • 症状与时间线结构化Qwen3-8B提取项目、术后天数、部位、变化趋势和用户描述。
  • 图片 OCR 与非诊断性观察Qwen3-VL-8B仅在用户授权上传后使用；不输出诊断或治疗结论。
  • 护理资料检索与草稿BGE + Qwen3-30B检索已审核资料后生成低风险护理建议。
  • 图文矛盾或风险线索复核InternVL3.5用独立视觉模型交叉复核，只输出需升级线索。
09 / RISK & COMPLIANCE

风险审查 Agent

  • 权限、敏感操作与硬性阻断规则 / 业务系统身份不符、未确认取消、敏感数据泄露等命中即阻断。
  • 广告、医疗边界与证据语义审查Qwen3-32B → R1高风险或意见冲突时，DeepSeek-R1 独立二次复核。
  • 图文高风险复核InternVL3.5仅在授权图片存在不确定性或风险线索时交叉复核。
  • 风险聚合、放行与人工接管确定性决策表输出通过、修订、阻止执行或转人工；模型不作最终裁决。

ADAPTATION PLAN / EVALUATE BEFORE TRAINING

开源模型微调策略：优先 LoRA，不做第一阶段全量微调

微调用于稳定任务格式、服务表达和审查标签，不用于写入项目疗效、价格、医生资质或医疗规则；这些事实仍由审核知识库、业务系统和规则引擎维护。

第一阶段：冻结主模型，先建立评测集

先以经专家审核的真实对话、风险案例和检索命中数据验证基础能力；未达到目标时才引入可回滚的 LoRA 适配器。

不建议第一阶段全量微调

全量微调成本高、回滚困难，可能损失通用能力并削弱模型家族之间的独立性。只有 LoRA 明确无法达到指标时才单独立项评估。
